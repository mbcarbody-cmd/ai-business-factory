# Lessons Learned

Purpose: convert execution mistakes into rules that improve future agent work.

## 2026-06-12 — Roles are not enough

Lesson: defining agent roles creates direction, but not execution. Execution starts when every role has a file-backed work surface, a status model, an owner, and proof requirements.

New operating rule: every agent output must update one of the OPS files or create a concrete product/sales/delivery artifact.

## 2026-06-12 — The bottleneck was the loop, not the idea quality

Lesson: the project did not lack ideas. It lacked the operating loop connecting research, task creation, build, review, deploy, sales, delivery and learning.

New operating rule: every task must state which part of the loop it advances.

## 2026-06-12 — Revenue must be visible inside operations

Lesson: if revenue operations and CFO economics are not tracked, agents can produce work without knowing whether it moves money.

New operating rule: P0 tasks must connect to revenue, deploy, delivery, QA, CFO or core OS closure.
