# Repo Work Accounting

This is the internal operating layer for the repository.

It is not a separate customer product. It tracks what the CEO, agents and builders are doing inside this repo.

## Purpose

Every action in the repo must be connected to one of these outcomes:

1. Build product
2. Improve product
3. Prepare sales material
4. Contact potential buyer
5. Move toward invoice
6. Deliver paid pilot

If a task does not move one of these outcomes, it is low priority.

## Required work log fields

- date
- worker or agent
- product
- task type
- task description
- output path
- status
- business value
- next action

## Task types

- repo_setup
- product_build
- landing_page
- tool_build
- sales_copy
- outreach
- target_research
- deployment
- bugfix
- customer_delivery
- invoice

## Status values

- planned
- doing
- done
- blocked
- shipped
- sold

## Daily CEO rule

Every day must produce at least one of:

- a finished tool
- a sales page
- an outreach pack
- a deployed demo
- a target list
- a buyer conversation
- an invoice text

## Repo done gate

The repo is not considered productive unless it has:

- at least one sellable product
- a public demo or install path
- a buyer list
- outreach text
- pricing
- delivery SOP
- next action
