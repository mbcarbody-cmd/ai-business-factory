# Workforce Turbocharge Gap Plan

Date: 2026-06-15
Owner: Chief Learning Officer + CEO / Master Agent
Status: active
Purpose: identify where the ecosystem workers are stuck, what knowledge is missing, and which training upgrades must be injected into agents before they can close revenue, deploy, QA, CFO, delivery and Parts Seller OS tasks.

## Current bottleneck verdict

The ecosystem is not primarily blocked by missing roles or missing documentation. The repo already has task board, agent memory, product gates, deploy loop, QA scorecard, revenue pack, CFO gate, delivery playbook paths and marketplace foundations.

The main blocker is execution proof conversion:

`repo_output_created -> public_verified -> QA_passed -> exact_leads_verified -> payment_path_attached -> paid_pilot_collected -> delivery_verified -> learning_synced`

Until this chain is closed, the system is operational but not fully business-complete.

## Top 7 places where the factory is stuck

1. Revenue proof gap
   - Problem: seed segments and target types exist, but exact public company rows are not verified enough to count as pipeline movement.
   - Missing worker skill: public lead verification, buyer-pain hypothesis, CRM hygiene, follow-up discipline.
   - Required output: at least 50 exact used-parts seller rows with source_url, contact_channel, pain hypothesis, offer, stage and next_action.

2. Payment path gap
   - Problem: pilots have price logic, but quote -> invoice -> payment confirmation is not closed.
   - Missing worker skill: payment links, invoice drafts, bank instructions, quote templates, paid-pilot acceptance rules.
   - Required output: one ready payment path for 300/600/900 EUR pilot packages before delivery starts.

3. Public deploy proof gap
   - Problem: static/local templates exist, but independent public URL smoke-test is not fully closed.
   - Missing worker skill: GitHub Pages/Vercel/Netlify deploy, release checklist, health-check, rollback, mobile smoke test.
   - Required output: public URL, release checklist result, rollback note and task-board proof update.

4. QA verdict gap
   - Problem: QA scorecard exists, but many outputs are not scored with PASS/BLOCKED verdict.
   - Missing worker skill: conversion QA, mobile QA, CTA QA, payment-path QA, blocker writing.
   - Required output: every sellable page/product has score >=80/100 or explicit Judge exception.

5. Delivery proof gap
   - Problem: 72h pilot rules exist, but no completed pilot-to-handoff proof exists yet.
   - Missing worker skill: intake, scope control, sample-data normalization, delivery checklist, client handoff, maintenance upsell.
   - Required output: one pilot record with intake, sample data, delivered dashboard, QA, handoff and next upsell.

6. Domain-depth gap for Parts Seller OS
   - Problem: rules exist, but workers need more real-world used-parts seller edge cases.
   - Missing worker skill: OEM ambiguity, fitment confidence, condition grading, RHD/LHD differences, storage capacity, low-value part handling, returns/warranty, marketplace listing readiness.
   - Required output: 100 realistic part scenarios turned into tests across category, fitment, location, price, listing status, reserve/order and dead-stock.

7. Learning-to-product gap
   - Problem: content/competitor findings and AI capability findings can stay as notes instead of becoming product/UI/sales changes.
   - Missing worker skill: extract rule -> normalize -> test -> update product -> QA -> sync to memory.
   - Required output: every important competitor/content pattern becomes at least one hook, one landing block, one outreach line or one product rule.

## Training injections to add immediately

1. Proof Ladder Training
   - Every worker must state which proof level it is producing: repo, local, URL, QA, lead, payment, client or revenue.

2. Real Seller Simulation Pack
   - Add 100 messy used-part scenarios covering OEM errors, missing photos, RHD/LHD, condition, fitment uncertainty, bulky storage, low-value parts and dead-stock.

3. Lead Verification Drill
   - Every Revenue/CI worker must verify exact company rows with source_url, contact_channel, pain_hypothesis and confidence.

4. Payment Path Drill
   - Every Revenue/CFO worker must be able to create quote/invoice/payment instruction for 300/600/900 EUR pilots.

5. Deploy Proof Drill
   - Every Deploy worker must record public URL, mobile smoke test, CTA check and rollback path.

6. QA Veto Drill
   - QA agents must block outputs that have no CTA, no price, no proof, no payment path, no URL or generic language.

7. Product-to-Revenue Drill
   - Every product worker must connect feature -> buyer pain -> price -> CTA -> delivery proof.

8. Learning Sync Drill
   - Every lesson must become one product rule, one test, one page/copy improvement or one task-board update.

## New KPIs for worker intelligence

- Proof conversion rate: % of tasks moved from repo_output_created to verified proof.
- Revenue row quality: % of lead rows with exact company/contact/source/pain/next_action.
- QA block rate: weak outputs blocked before user sees them.
- Deploy proof age: days since last verified public URL smoke test.
- Payment readiness: number of products with invoice/payment/quote path.
- Delivery readiness: number of offers with intake, 72h scope and handoff.
- Learning sync rate: number of lessons converted into product rules/tests/assets.

## Next single highest-value action

Create a `proof_ladder` field on active tasks and force every active worker to classify output as one of:

- doc_only
- repo_output_created
- local_verified
- public_url_verified
- qa_passed
- exact_leads_verified
- payment_path_attached
- paid_pilot_collected
- delivery_verified
- revenue_verified

This prevents the system from confusing documentation with execution.
