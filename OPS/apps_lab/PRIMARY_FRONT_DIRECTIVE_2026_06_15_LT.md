# Apps Lab Primary Front Directive

Date: 2026-06-15
Owner: CEO / Master Agent + Opportunity Lab GM
Status: active

## Decision

The heavy operating-system repo is no longer the primary product front.

Primary front is now Apps Lab: lightweight app and novelty product experiments that can be tested fast with mini prototypes and real user-interest signals.

## Why

The heavy repo work is useful as internal infrastructure, but it is too slow as the main revenue/product front. The system must not default back to building a large operating system when the user has already chosen a lighter product-discovery path.

## Operating rule

Every day, the system must produce or improve at least one Apps Lab artifact:

- app idea shortlist;
- scored MVP candidate;
- landing page copy;
- mini prototype;
- user test script;
- public-data research note;
- competitor teardown;
- monetization path;
- outreach/test plan.

## Current priority lanes

1. AI Date Planner / anti-swipe meeting assistant.
2. AI Wingman / message helper.
3. NoSwipe curated intro experiment.
4. Micro social / hobby-meet experiments.
5. Mini-games or simple viral apps only if they are faster than dating/social experiments.

## Hard rule

No large architecture, no marketplace-scale build, no domain purchase, no heavy backend, and no app store build before a mini prototype proves user interest.

## Memory rule

The user must not need to repeat this direction daily. Any future task-board review must check this directive before proposing heavy repo work.
