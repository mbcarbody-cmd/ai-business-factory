# 72h Delivery Playbook

Owner: DELIVERY-2 72h Delivery Captain

## Purpose

Deliver a paid pilot without chaos.

## Before payment

1. Intake form completed.
2. Scope accepted by Delivery.
3. Price/margin checked by CFO.
4. Product promise checked by Judge.
5. Required client access confirmed.

## Hour 0-4: scope lock

- Confirm exact output.
- Confirm not-included list.
- Create delivery task in task board.
- Collect required inputs/access.

## Hour 4-24: build first usable version

- Build smallest useful workflow.
- Avoid extra features.
- Record blockers immediately.
- Keep output visible in repo or delivery doc.

## Hour 24-48: QA and polish

- Run critic checklist.
- Fix critical/high issues.
- Prepare simple client usage instructions.
- Confirm CTA, forms, automations or workflows work.

## Hour 48-72: handoff and upsell

- Send final output.
- Send usage instructions.
- List known limits.
- Offer maintenance.
- Ask for feedback/testimonial/referral.

## Delivery block rules

Delivery is blocked if:

- no intake,
- no access,
- no scope,
- no QA,
- no handoff,
- promise is bigger than package.
