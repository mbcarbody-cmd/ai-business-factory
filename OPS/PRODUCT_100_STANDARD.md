# 100 Percent Product Standard

The word demo is not the goal.

A product that is not usable by real users is only a prototype. The target is a complete working product.

## Product stages

### Stage 0: idea
Only a direction or problem.

### Stage 1: prototype
Basic proof that the concept can work.

### Stage 2: internal alpha
Works for the team with known limits.

### Stage 3: beta
Works for selected users with support.

### Stage 4: release candidate
Feature complete, tested and deployable.

### Stage 5: final working product
Ready for real users, support, updates and sales.

## A final working product must have

- login and role permissions
- stable database
- finished core workflow
- mobile friendly interface
- clear error handling
- backups
- deployment script
- monitoring and logs
- test checklist
- security review
- user guide
- support process
- pricing and package
- public page
- target list
- delivery plan

## Security defense standard

Security agents think like defenders. They study how systems fail so they can prevent failures in our own systems.

They check:

- weak passwords and missing access control
- exposed environment variables
- unsafe file upload
- missing input validation
- SQL or command injection risk
- broken session handling
- public admin panels
- server permissions
- missing backups
- missing logs
- unprotected APIs

## Release rule

No product is called final until QA, Security, DevOps, Product and Sales all mark it ready.
