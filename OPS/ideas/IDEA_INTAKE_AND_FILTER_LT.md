# Idea Intake and Filter LT

Date: 2026-06-12
Owner: CEO / Master Agent + COO-1 Execution Architect
Purpose: idėjas paversti ne chaosu, o kontroliuojamu pipeline: capture -> score -> decide -> task -> test -> learn.

## Idėjos eiga

1. Capture — užrašyti idėją.
2. Clarify — vienu sakiniu aprašyti vertę.
3. Score — įvertinti pagal kriterijus.
4. Compare — palyginti su alternatyvomis.
5. Gate — priskirti product/revenue/marketplace/delivery gate.
6. Task — sukurti task board įrašą.
7. Test — padaryti mažiausią testą.
8. Learn — įrašyti pamoką į memory.

## Idėjos kortelė

Kiekviena idėja turi:

- id,
- title,
- one sentence value,
- target buyer/user,
- pain,
- revenue path,
- margin logic,
- build effort,
- delivery effort,
- QA concern,
- competitor reference,
- first test,
- owner,
- status,
- proof path.

## Idėjų statusai

- captured,
- clarify_needed,
- scored,
- approved_for_test,
- converted_to_task,
- paused,
- completed,
- archived.

## Scoring

Vertinti 1-5:

- pain strength,
- willingness to pay,
- speed to test,
- margin potential,
- strategic fit,
- marketplace/internal OS value,
- delivery simplicity,
- learning value.

## Privalomi klausimai prieš build

1. Ar yra realus pirkėjas arba vidinis workflow?
2. Ar problema pakankamai skauda?
3. Kokia alternatyva rinkoje?
4. Kodėl mes galim geriau?
5. Koks mažiausias testas?
6. Kokia kaina arba sutaupymas?
7. Kas turi būti pristatyta per 72h arba MVP?
8. Kur įrašysime proof?

## Prioritetų taisyklė

Pirmiau eina idėjos, kurios:

- greičiausiai veda į pajamas,
- stiprina delivery repeatability,
- mažina chaosą,
- gerina marketplace/internal OS,
- kuria reusable asset,
- turi aiškų pirkėją.
